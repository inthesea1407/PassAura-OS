# Conformance vectors

Status: draft. The vectors are generated by this repo's own Rust code, so they
check that the code stays stable and give other implementations something to
compare with. They are not independent verification.

- `tests/vectors/allowlist_v2.json`: 17 cases for `pos_gate::allowlist_v2::verify_v2`
  (valid, downgrade, expiry, tamper, retired or unknown signer, empty keyring, bad window).
  Signature is Ed25519 over the sorted-key canonical JSON without `signature_hex`.
  The test keys are public and protect nothing.
- `tests/vectors/audit_chain.json`: 9 cases for the audit hash chain.
  Removing the newest records is not detected without an external anchor, and the
  `tail_truncated_undetectable` case records that.

Tests: `crates/pos-gate/tests/conformance_v2.rs`, `crates/pos-core/tests/conformance_audit.rs`.
They fail if the committed file differs from what the code produces, then replay
the committed file through the verifier.
Regenerate: `UPDATE_VECTORS=1 cargo test -p pos-gate --test conformance_v2` (same for pos-core).
Regeneration should be a reviewed change.
